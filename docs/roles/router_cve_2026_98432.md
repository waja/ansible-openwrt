# CVE-2026-98432 mitigation

This role manages a temporary firewall workaround for CVE-2026-98432 on
OpenWrt systems using firewall4 (fw4). It is independent of the normal
router playbook and does not install packages, change kernel settings, or
decide whether a vendor kernel contains the upstream fix.

## State

| Variable | Default | Meaning |
| --- | --- | --- |
| `router_cve_2026_98432_state` | required (no default) | Explicitly install (`present`) or remove (`absent`) the workaround |
| `router_cve_2026_98432_apply_runtime_changes` | `true` | Reload fw4 and verify the active nftables table |

The workaround is deliberately not selected automatically from the kernel
version. Distribution kernels may backport fixes, so the operator must verify
the vendor's security advisory before choosing the desired state explicitly.

## Install

For a single router:

```bash
ansible-playbook -i inventory.ini playbooks/cve-2026-98432.yml \
  --limit router1 -e router_cve_2026_98432_state=present
```

Review the impact before enabling it: IPv4 TCP packets carrying IPv4 header
options are dropped. Ordinary IPv4 TCP without IP options and IPv6 are not
matched by the rule.

The role owns only:

- `/etc/cve_2026_98432.nft`
- UCI include `firewall.ansible_cve_2026_98432`
- the exact `/etc/sysupgrade.conf` entry for that file

It validates the generated fw4 ruleset before reloading the firewall when
runtime changes are enabled, then checks the active table after reload. If an
operation fails, the role restores the previous owned UCI include and ruleset
file and restores only its own sysupgrade entry, preserving unrelated entries.
If a firewall reload was attempted, recovery reloads the restored fw4
configuration and verifies the mitigation table. It does not take or replay a
snapshot of the live nftables ruleset. fw4 submits its generated ruleset to
nftables as a batch; the recovery path relies on that normal apply mechanism
rather than maintaining a second copy of kernel state. A failed `fw4 check`
does not cause an unrelated firewall reload.

## Remove

After verifying that the running vendor kernel contains the fix:

```bash
ansible-playbook -i inventory.ini playbooks/cve-2026-98432.yml \
  --limit router1 -e router_cve_2026_98432_state=absent
```

The role removes only its own UCI include, ruleset file, and sysupgrade
entry. It also removes the dedicated nftables table, which is outside the
fw4-generated table and is not automatically deleted by an fw4 reload.

## Check mode and limitations

Set `router_cve_2026_98432_apply_runtime_changes: false` to avoid running
`fw4 check` or reloading fw4. The role still performs a read-only probe of the
dedicated nftables table. If that probe conclusively establishes that the table
is absent, the role stages a disabled UCI include and the sysupgrade entry. If
the probe is inconclusive, it stages only the ruleset file and does not create
an ownership marker or a loadable include. An existing owned include is left
in its current enabled state. This mode does not validate the generated fw4
ruleset or prove that the rule is active. Removal is refused because the
independent mitigation table cannot be safely removed without runtime
inspection; deleting its persistent include could otherwise orphan the active
packet filter.

The Molecule Docker scenario tests both conclusive-absence and inconclusive
probe outcomes without requiring `CAP_NET_ADMIN`. A separate CI
network-namespace test applies the production nftables artifact and checks IPv4
TCP with and without IP options on INPUT and FORWARD, plus IPv6 compatibility.
The fw4 include/reload path is validated on the documented OpenWrt runtime
target.

The runtime-validated target is OpenWrt 25.12.5 on an x86/64 virtual
machine using the standard fw4 nftables backend. Turris OS 9.x is an intended
compatibility target but has not been runtime-validated. The workaround
does not cover bridge/L2, VLAN-aware bridge, tunnel, XDP, or other datapaths
that bypass the tested IPv4
prerouting hook. Hardware flow-offload behavior has not been validated.

This is a temporary packet-filtering workaround, not a kernel fix. Install
the vendor kernel update and verify its patch status before removing it.
