# CVE-2026-98432 mitigation

This role manages a temporary firewall workaround for CVE-2026-98432 on
OpenWrt systems using firewall4 (fw4). It is independent of the normal
router playbook and does not install packages, change kernel settings, or
decide whether a vendor kernel contains the upstream fix.

## State

| Variable | Default | Meaning |
| --- | --- | --- |
| `router_cve_2026_98432_state` | required (no default) | Explicitly install (`present`) or remove (`absent`) the workaround |
| `router_cve_2026_98432_apply_runtime_changes` | `true` | Reload fw4 and verify the active nftables table |

The workaround is deliberately not selected automatically from the kernel
version. The role reports the running kernel and classifies the 6.6 stable
series against the upstream 6.6.159 fixed threshold; other series are reported
as unknown. This is version information only: distribution kernels may
backport fixes, so the operator must verify the vendor's security advisory
before choosing the desired state explicitly.

## Install

For a single router:

```bash
ansible-playbook -i inventory.ini playbooks/cve-2026-98432.yml \
  --limit router1 -e router_cve_2026_98432_state=present
```

Review the impact before enabling it: IPv4 TCP packets carrying IPv4 header
options are dropped. Ordinary IPv4 TCP without IP options and IPv6 are not
matched by the rule.

The role owns only:

- `/etc/cve_2026_98432.nft`
- UCI include `firewall.ansible_cve_2026_98432`
- the exact `/etc/sysupgrade.conf` entry for that file

It validates the generated fw4 ruleset before reloading the firewall when
runtime changes are enabled, then checks the active table after reload. If
an operation fails, the role restores only its owned UCI include, ruleset file,
and sysupgrade entry, then reports whether the recovery reload succeeded.

## Remove

After verifying that the running vendor kernel contains the fix:

```bash
ansible-playbook -i inventory.ini playbooks/cve-2026-98432.yml \
  --limit router1 -e router_cve_2026_98432_state=absent
```

The role removes only its own UCI include, ruleset file, and sysupgrade
entry. It also removes the dedicated nftables table, which is outside the
fw4-generated table and is not automatically deleted by an fw4 reload.

## Check mode and limitations

Set `router_cve_2026_98432_apply_runtime_changes: false` to stage the UCI,
nftables file, and sysupgrade configuration without running `fw4 check` or
reloading fw4. This is useful for configuration-only runs; it does not
validate the generated fw4 ruleset or prove that the rule is active. Removal
is refused in this mode when the independent mitigation table is still live,
because deleting its persistent include would otherwise orphan the active
packet filter.

The Molecule Docker scenario runs configuration-only because it does not grant
the container `CAP_NET_ADMIN`. A separate CI network-namespace test applies
the nftables rule and checks IPv4 TCP with and without IP options on INPUT and
FORWARD, plus IPv6 compatibility. The fw4 include/reload path is validated on
the documented OpenWrt runtime target.

The validated target is OpenWrt 25.12 with the standard fw4 nftables
backend. Turris OS 9.x is an intended compatibility target but has not been
runtime-validated. The workaround does not cover bridge/L2, VLAN-aware
bridge, tunnel, XDP, or other datapaths that bypass the tested IPv4
prerouting hook. Hardware flow-offload behavior has not been validated.

This is a temporary packet-filtering workaround, not a kernel fix. Install
the vendor kernel update and verify its patch status before removing it.
